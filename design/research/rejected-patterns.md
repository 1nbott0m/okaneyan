# Rejected patterns — anti-template ledger

| Pattern / example | Evidence | Why it fails MoneyWise | Keep only if | Decision |
|---|---|---|---|---|
| AI/fintech marketplace hero: night-sky + glowing horizon + animated charts/countups | Avvyren listing describes exactly this combination: https://www.framer.com/marketplace/templates/avvyren/ | Advertising-style glow and auto-counted figures make an unconnected demo feel falsely live. | A specific data state needs a non-ambient light cue, and it never compromises contrast. | Reject as direction; no code/assets copied. |
| Bento dashboard card grid | Fintly listing: lime/teal, mockup hero, bento grid and animated counters: https://www.framer.com/marketplace/templates/71805/ | Similar equal tiles erase the unique hierarchy between actual, free, protected and expected. | A dense list is genuinely scannable as a set of distinct tasks. | Avoid for Overview. |
| Decorative 3D orbits/particles | Repeated in current brief anti-goals and marketplace listings; no project-specific data mapping | “Gravity” becomes a space game; motion can imply a real balance change when only a hypothetical state changed. | Every object's type, value, scale and connection has a legible financial explanation. | Rejected as primary design. Gravity now uses an editorial register; the former orbit is retained only in older before screenshots. |
| Gradient glass on every surface | Japanese trend sources mention glass on some products; no evidence that this helps MoneyWise's daily ledger | Competes with precise values, degrades table hierarchy and resembles generic finance marketing. | Limited to a documented, tested material surface. | Reject as global material. |
| Cursor trails and perpetual cinematic loops | Sileent describes cursor identity; Codrops examples show expressive continuous loops | Desktop-only, energy-consuming, unrelated to cash decisions. | A bounded one-shot cue improves origin/destination comprehension. | Do not implement for daily Overview. |
| Small mono text everywhere | Common fintech template trope; CoFo Drifter candidate is not in repository/licensed | Dense Russian copy becomes hard to read; merely making labels mono does not create ownership. | Tabular numerals on amounts/IDs with a readable Cyrillic body face. | Restrict data font role; verify actual glyphs/license first. |
| Unsupported “live” and “bank locked” language | product domain and main MoneyWise functional brief | Claims integration and financial action that are absent. | Never in this product without an actual backend/bank capability. | Explicitly prohibit. |

## User-visible quality rule

An unusual object must explain the user's financial situation. If it does not increase comprehension, remove it. One expressive object per screen; transaction rows remain quiet and information-dense.
