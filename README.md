# okaneyan. — Personal Finance

Нативное iPhone-приложение для личных финансов: показывает расчёт свободных денег, помогает проверить покупку, хранит план платежей и импортирует банковские операции из CSV. `MoneyWise` остаётся внутренним именем Xcode-проекта и bundle target.

## Текущее состояние

- Swift + SwiftUI; финансовая логика вынесена в `Sources/MoneyCore`.
- Локальная SwiftData база без аккаунта и облачной синхронизации.
- Есть счета с ручным балансом, операции, CSV-предпросмотр, категории, бюджеты, обязательства, подписки, долги, цели, прогноз и локальные напоминания.
- Импорт выписок читает UTF-8 (включая BOM) и Windows-1251, CSV-разделители `;`/`,` и табуляцию в TSV, знаковые суммы и раздельные колонки прихода/расхода или дебета/кредита. Разделитель определяется по заголовку; неоднозначный формат отклоняется. Распознаёт русские заголовки назначения/контрагента и предпочитает дату операции; неоднозначные даты, суммы, лишние/недостающие колонки и валюты отклоняются, а не угадываются.
- Импорт предлагает вероятные еженедельные/ежемесячные исходящие траты, включая внешние переводы, и отсекает нулевые/отрицательные суммы; пользователь сам подтверждает добавление в план.
- Проверка покупки не считает ожидаемый доход уже имеющимися деньгами и сообщает, когда данных недостаточно.
- Именной резерв можно явно связать с целью или конкретным подтверждённым платежом: расчёт не вычитает одну и ту же сумму дважды, а старые/невалидные связи безопасно остаются отдельными резервами. Миграция и повторное открытие старой SwiftData базы ещё требуют проверки в Xcode.
- Главная показывает максимальный средний расход в день до следующего поступления с учётом резерва, целей и подтверждённых обязательств; при дефиците, неактуальном балансе или горизонте дальше двух лет показывает предупреждение вместо безопасной цифры. График прогноза ограничен 90 днями.
- На главном экране есть цветной статус плана; без достаточной истории обычных расходов приложение не говорит, что план устойчив, и не даёт уверенный ответ по покупке. Проведённые операции, уже явно связанные с плановыми платежами, исключаются из оценки переменных расходов, чтобы не резервировать регулярную трату повторно.
- Главный экран показывает динамику расходов за неделю или месяц и распределение по категориям; графики следуют настройке скрытия сумм.
- Проверка покупки учитывает желаемую дату, выбранную категорию и лимит бюджета категории. Запланированная покупка не считается плохой, но проходит тот же расчёт резерва и обязательств. Даты до сегодня или после следующего ожидаемого поступления не получают ложный безопасный вердикт.
- При ошибке записи бюджета, операции, счёта, цели, долга, плана или настроек приложение показывает ошибку и сохраняет открытый экран, чтобы не выдавать несохранённое изменение за успешное. Напоминания меняются после успешного сохранения.
- Редактирование счёта, операции, платежа и настроек использует локальный черновик: выход без сохранения не меняет финансовую модель.
- В предпросмотре CSV можно выбрать счёт-источник: повторная выписка, даже если файл переименован или перемещён, распознаёт точные совпадения строк. Без привязки приложение предупреждает о риске дублей; баланс счёта от импорта не меняется.
- Если CSV содержит явно распознанный ID банковской операции, импорт использует его для подавления дублей и обновления статуса ожидающей операции только внутри выбранного счёта; без выбранного счёта остаётся файловый отпечаток.
- Вкладка операций загружает историю порциями по 100 записей с поиском по магазину/получателю и фильтрами по счёту и категории; обзор загружает только недавние операции. Поиск дублей для выписки проходит отдельно от UI-контекста и показывает индикатор подготовки.
- Доход можно пометить как поддержку родителей или другой доход. Входящий перевод от родителей остаётся переводом, но его источник сохраняется отдельно от заработанного дохода. CSV распознаёт явные упоминания родителей; неясные поступления не получают эту метку автоматически.
- CSV-строки с признаками перевода отдельно классифицируются как входящие и исходящие переводы. Входящий перевод не считается заработанным доходом, исходящий остаётся расходом, пока пользователь явно не подтвердит, что это движение между своими счетами.
- Для переводов с выписками двух включённых в план счетов приложение предлагает возможную пару по точной сумме, противоположному направлению и интервалу до 72 часов. Пользователь подтверждает обе стороны отдельно; одиночные и неоднозначные операции автоматически не скрываются.
- Подтверждённая пара хранится отдельной локальной записью. Если пользователь меняет её дату/тип, снимает отметку, удаляет сторону, отключает счёт из финансового плана или удаляет его, связь удаляется, а оставшаяся операция снова учитывается в денежном потоке.
- Операция, связанная с плановым платежом, уменьшает обязательство только если её источник — включённый счёт. Платёж с выключенного/удалённого счёта не влияет на активный прогноз; ручные операции без счёта остаются допустимыми.
- Исправленную категорию покупки можно запомнить для будущих импортированных покупок с тем же нормализованным названием получателя; возвраты, доходы и переводы сохраняют собственные типы категорий. Правило хранится локально и удаляется вместе с данными.
- Связанный с целью платёж открывает редактор цели, чтобы изменение взноса пересчитывало цель и точный последний платёж вместе, а не оставляло их расходящимися.
- Удаление графика взносов оставляет цель в списке, но сбрасывает плановый месячный взнос и ссылку на удалённый платёж.
- Платёж по долгу нельзя удалить отдельно от долга: сначала измени план долга или подтверди его фактическое погашение. Удаление записи долга требует отдельного подтверждения. При удалении цели или долга связанное системное напоминание (включая уже доставленное) отменяется после успешного сохранения.
- План долга резервирует платёж каждый месяц до подтверждённого нулевого остатка и не считает платёж внесённым по календарю. Размер резерва не превышает подтверждённый остаток; напоминание можно настроить при создании и редактировании долга.
- Реальные банковские API ещё не подключены. Добавление счёта пока означает ручной баланс; никакие банковские логины/пароли не запрашиваются.
- Автосинхронизация обязательна для желаемого MVP, но сейчас заблокирована ограничениями доступа: ежедневная загрузка CSV пользователю не подходит, серверы и посредники исключены, а ни один банк ещё не подтвердил прямой API для этого личного iOS-клиента. Документация Сбера и Альфы указывает на бизнес-подключение и серверные секреты/сертификаты; для Ozon личный API публично не подтверждён. Это не доказывает, что API никогда не будет доступен, и не является выводом о лицензии. Подробности и официальные источники — в [проверке доступа к банковским API](.agent/bank-api-eligibility.md).
- Автосинхронизации пока нет. Банк России опубликовал рекомендованные стандарты чтения счетов физических лиц, но Open API предназначены для организаций-участников, а допуск этого standalone iOS-приложения и native-поток без сервера/посредника не подтверждён. Сберские выписки относятся к СберБизнес; Alfa показывает B2C/партнёрские API, но не подтверждает самостоятельный клиент без backend; публичный API чтения операций личной Ozon Карты, личного счёта ВТБ и российского ОТП не подтверждён. Это пробел подтверждения доступа, а не доказательство отсутствия API или требуемой лицензии. Подробности и официальные источники находятся в [анкете доступа к банковским API](.agent/bank-api-eligibility.md).
- Внешний ИИ отложен по решению пользователя. Локальная модель может быть рассмотрена отдельно.

## Проверки на доступной среде

```sh
swift run moneywise-checks
swift run moneywise-demo
swiftc -frontend -parse iOSApp/MoneyWiseApp.swift Sources/MoneyCore/*.swift Tests/MoneyCoreTests/*.swift
plutil -lint MoneyWise.xcodeproj/project.pbxproj
```

Ядро содержит 380 поведенческих проверок денежных расчётов, точности копеек и дат, свежести баланса, импорта, парных переводов, целей, долгов, резервов, аналитики и прогнозов. Проект задаёт Data Protection entitlement, но его подпись и фактическую защиту SQLite-файлов, полную сборку iOS, запуск на симуляторе или iPhone, Face ID, VoiceOver и работу уведомлений нужно проверить в полном Xcode.

Чтобы открыть приложение на iPhone, открой `MoneyWise.xcodeproj` в Xcode и запусти на симуляторе или устройстве. Этот проект был создан в среде без полного Xcode/iOS SDK, поэтому настоящая сборка, установка и сценарии на iPhone пока не проверены. Синтаксическая проверка Swift не заменяет сборку Xcode.

## Структура

- `iOSApp/MoneyWiseApp.swift` — SwiftUI-интерфейс, SwiftData-модели и локальные сценарии приложения.
- `Sources/MoneyCore` — денежная модель, проверка покупок, аналитика расходов, CSV-импорт, поиск регулярных трат и прогноз расходов.
- `Tests/MoneyCoreTests` — исполняемые проверки ядра (`swift run moneywise-checks`).
- `MoneyWise.xcodeproj` — нативная iOS-цель, минимальная версия iOS 17.
- `PRODUCT_SPEC.md` — продуктовые решения, ограничения и исследование доступа к API банков.
- `.agent/tasks/ios-mvp-roadmap.md` — этапы, критерии и оставшиеся блокеры.
