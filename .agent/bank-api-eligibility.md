# Запрос банку: прямое подключение личного счёта из iOS-приложения

Используй официальный канал поддержки банка или его developer/API-портала. Не отправляй банковский пароль, одноразовый код, номер карты целиком, выписку или токены.

## Текст запроса

Здравствуйте! Я разрабатываю личное приложение для iPhone, которым буду пользоваться только сам для локального учёта расходов. Приложение не будет передавать банковские данные на мой сервер, сервер третьего лица или агрегатор; база и токены останутся на iPhone. Мне нужно только чтение собственных счетов, остатков и истории операций.

Подскажите, пожалуйста:

1. Разрешает ли банк физическому лицу подключить собственный standalone iOS-клиент к API личного счёта, без регистрации компании/ИП, статуса партнёра и серверной части?
2. Есть ли опубликованный API именно для личных счетов (не бизнес-счёта, эквайринга или API продавца)? Пришлите ссылку на официальную документацию и точные read-only scopes/методы для счетов, остатков и операций.
3. Разрешён ли native OAuth через системный браузер и redirect обратно в iOS-приложение, с PKCE, без backend для обмена кода на токен?
4. Можно ли хранить пользовательский refresh token только в защищённом хранилище iPhone (Keychain) и обновлять его непосредственно из приложения?
5. Требуются ли `client_secret`, mTLS/закрытый сертификат или ключ, который по условиям банка нельзя хранить в приложении и который требует доверенный backend?
6. Можно ли получать историю операций автоматически при открытии приложения и фоновым обновлением iOS? Каковы глубина истории, лимиты запросов и срок действия токенов?
7. Есть ли песочница для личного iOS-клиента? Есть ли плата, договор, сертификация или юридические/технические условия для личного использования?
8. Если стандартный API требует backend/партнёра: существует ли отдельный официальный вариант прямого подключения без серверов и посредников?

Пожалуйста, подтвердите ответ ссылками на официальные условия или документацию. Если такой сценарий не поддерживается, достаточно прямо сообщить об этом.

Спасибо!

## Как оценить ответ

- **Можно исследовать адаптер:** банк официально подтверждает personal account API, native iOS OAuth, on-device token refresh, read-only scopes и доступную sandbox без backend/посредника.
- **Нельзя подключать в этом проекте:** требуются сервер, интегратор/агрегатор, коммерческий партнёр, секрет/сертификат для доверенного backend, автоматизация входа в банковское приложение или недокументированный endpoint.
- **Недостаточно данных:** ответ только «у нас есть API» без подтверждения доступа к личному счёту и допустимого способа подключения из iOS.

## Проверка официальных публичных источников (2026-10-29)

Это проверка опубликованной документации, а не письменный ответ банка. Не считать её юридическим заключением или подтверждением доступа.

- Банк России указывает, что обмен Открытыми API происходит между информационными системами двух организаций; пользователями/поставщиками могут быть организации, отвечающие установленным критериям участника. Одновременно в опубликованном комплексе есть отдельные стандарты для получения согласия и информации по счетам физических лиц. Это описывает владельца счёта/тип данных, но само по себе не подтверждает, что частный standalone-клиент может стать участником и подключаться напрямую.
- Поэтому пока нельзя утверждать, что обязательно нужна именно «лицензия»: требуется выяснить статус участника, организационные и ИБ-критерии, а также возможность банковского допуска. Одного согласия владельца счёта недостаточно, чтобы доказать допустимость произвольного прямого клиента.
- [Документация OAuth Sber API](https://developers.sber.ru/docs/ru/sber-api/start/oauth), обновлённая 31.08.2026, прямо говорит, что запросы выполняются от имени пользователя СберБизнес; авторизация иных организаций описана через SberBusiness ID. Это не подтверждает личные розничные счета.
- [Официальный FAQ Alfa API](https://developers.alfabank.ru/faq) описывает production token endpoints, client_secret и сертификаты; инструкция подключения требует оформить production integration, TLS-сертификат и client_secret/API Key. Доступ личного пользователя к собственному розничному счёту через public native iOS client и PKCE в доступных материалах не подтверждён.
- [Официальная справка Ozon](https://docs.ozon.ru/common/oplata/bank-statements/) объясняет получение выписок через приложение, сайт, офис или банкомат. Это подтверждает пользовательский экспорт, но не программный API личного счёта.

Это не доказывает запрет личного приложения и не устанавливает, что конкретно этому проекту нужна лицензия; однако одного согласия клиента и наличия стандартов для счетов физлиц недостаточно, чтобы считать standalone-клиент допущенным участником.

**Вывод:** на дату проверки ни один из пяти банков не получил статус «можно подключать» по всем критериям из анкеты. Следующий шаг — официальный запрос по тексту выше. До письменного подтверждения не добавлять банковские пароли, web scraping, чтение SMS/push, скрытые endpoint или OAuth-заглушки. Автосинхронизация остаётся неподтверждённым обязательным требованием MVP.

## Повторная проверка официальной документации — 29.10.2026

- **Сбер:** официальное описание сценария выписки относится к расчётно-кассовому обслуживанию для компаний и требует пользовательский профиль в СберБизнес. Наличие REST-методов выписки само по себе не даёт основания применять их к личному счёту и standalone iOS-клиенту: [use case выписки](https://developers.sber.ru/docs/ru/sber-api/scenarios/rko/statements/overview), [справочник методов](https://developers.sber.ru/docs/ru/sber-api/specifications/statement/statement-overview).
- **Альфа-Банк:** портал показывает продукты для бизнеса и сведения о счетах физических лиц в сценариях работы с клиентами; документация Open Banking использует OAuth bearer token и стандарт Банка России, но публичные материалы не подтверждают, что личный клиент может подключить приложение только на своём iPhone без backend или статуса партнёра. Это остаётся вопросом банку, а не доказанным запретом: [портал разработчика](https://developers.alfabank.ru/), [метод выписки Open Banking](https://developers.alfabank.ru/products/alfa-api/documentation/articles/transactions/articles/statement-ob/v1/statement-ob).
- **Ozon Банк:** пользовательская справка подтверждает получение выписки через приложение/сайт/отделение/банкомат; найденный 1С ДиректБанк — сценарий интеграции бухучёта бизнеса. Ни один источник не подтверждает API чтения личного счёта из standalone iOS-приложения: [справка по выпискам](https://docs.ozon.ru/common/oplata/bank-statements/), [1С ДиректБанк для бизнеса](https://finance.ozon.ru/blog/b2b/article/kak-podklyuchit-1c-direct-bank).

**Решение:** ни для одного приоритетного банка не добавлять адаптер или экран «подключено» без прямого подтверждения условий. В этой среде остаются импорт локальной выписки и ручное ведение баланса; автоматическая синхронизация не реализована и не может считаться принятой.

## Уточнение по стандартам Банка России — 29.10.2026

На опубликованной странице Банка России теперь явно перечислены отдельные стандарты для физических лиц: методы получения согласия и методы получения счетов, балансов, карт и транзакций. Спецификация методов для физлиц указывает `Client Authorization code flow` для чтения счетов и данных, а спецификация согласия — `Client Credentials flow` и обязательную JWS-подпись. Стандарт по физическим счетам рекомендован к использованию организациями и описывает взаимодействие третьей стороны с поставщиком; FAQ Банка России определяет обе стороны Open API как организации, отвечающие критериям участника. Это важная техническая основа Open Finance, но не разрешение частному приложению самостоятельно зарегистрироваться, получить банковские credentials или вызвать API напрямую с iPhone. См. [официальный перечень стандартов](https://www.cbr.ru/fintech/api/prikladnye-standarty/), [методы для физлиц](https://www.cbr.ru/Content/Document/File/185573/20251219_od_2894.pdf), [методы согласия для физлиц](https://www.cbr.ru/Content/Document/File/185572/20251219_od_2892.pdf) и [FAQ об участниках Open API](https://www.cbr.ru/fintech/api/).

**Обновлённый вывод:** API-профиль для розничных данных физлиц существует на уровне стандарта; доступность этого профиля у конкретного банка и допуск MoneyWise как самостоятельного native iOS-клиента без backend остаются неподтверждёнными. Не говорить, что «API для физлиц не существует», и не делать вывод о необходимости лицензии без юридического ответа. Следующий безопасный шаг — получить у Сбера, Альфы и Ozon письменный ответ по вопросам из анкеты, особенно по регистрации приложения/участника, client credentials, JWS-ключу, redirect/OAuth и хранению/обновлению токена только в Keychain.

## Проверка требований к ключам и прямому размещению — 29.10.2026

- Документация Сбера уточняет, что production mTLS `.p12` сертификат требуется установить **на сервере**; production-сертификат получают в личном кабинете Sber API в СберБизнес или через поддержку. OAuth выполняется от имени пользователя СберБизнес. Это не подходит к текущему запрету MoneyWise на сервер и не подтверждает доступ к личному розничному счёту. Источники: [требования Sber API к TLS](https://developers.sber.ru/docs/ru/sber-api/start/tls), [OAuth и scopes](https://developers.sber.ru/docs/ru/sber-api/start/oauth).
- Для Alfa API инструкция подключения требует подключить Alfa-Бизнес и подписать договор интеграции; production требует TLS-сертификат и `client_secret`/`API Key`. Портал интеграций доступен сотруднику подключённой организации. API Key в документации относится к H2H и, среди перечисленных методов, к выпискам юрлиц. Это не подтверждает самостоятельное чтение своего личного счёта из приложения на iPhone. Источники: [подключение Alfa API](https://developers.alfabank.ru/products/alfa-api/documentation/articles/connection/articles/instruction/instruction), [доступ к порталу](https://developers.alfabank.ru/products/alfa-api/documentation/articles/selfservice/articles/intro/intro), [область применения API Key](https://developers.alfabank.ru/products/alfa-api/documentation/articles/api-key/api-key).
- Банк России подтверждает передачу данных по согласию клиента, но указывает, что участники обмена — организации, соответствующие критериям участника. Наличие опубликованных стандартов для счетов физических лиц само по себе не даёт standalone-приложению допуск к банковским API. Источники: [FAQ Банка России](https://www.cbr.ru/faq/fintekh/), [каталог стандартов](https://www.cbr.ru/fintech/api/prikladnye-standarty/).
- Для Ozon Банка в найденных публичных материалах подтверждён запрос выписки через пользовательские каналы; публичный API чтения операций личного счёта не найден. Это не доказывает отсутствие закрытого API.

**Решение для текущего MVP:** не обещать автосинхронизацию и не запрашивать банковский ключ, который нельзя получить для разрешённого personal/native сценария. Нельзя подтвердить, что ключи «вообще никогда» недоступны; подтверждено, что опубликованные onboarding и требования Сбера/Альфы сейчас не соответствуют выбранным ограничениям, а путь Ozon не найден. Ежедневный импорт выписки не является приемлемым целевым процессом пользователя, поэтому автосинхронизация остаётся **BLOCKED: требуется официальный допуск одного банка к direct iOS personal API без backend либо пересмотр запрета на посредника**. Лицензионный вывод не сделан.

## Повторная проверка OAuth и каталогов — 29.10.2026

- Страница сценария выписок Сбер API прямо маркирует use case как доступный компаниям и требует у пользователя профиль СберБизнес своей компании. FAQ по OAuth дополнительно описывает серверную часть приложения для обработки `redirect_uri` и быстрого обмена authorization code; это не совместимо с принятым запретом на любой backend без отдельного письменного разрешения банка на другой native flow. См. [сценарий выписок](https://developers.sber.ru/docs/ru/sber-api/scenarios/rko/statements/overview) и [FAQ OAuth/token](https://developers.sber.ru/docs/ru/sber-api/faq/overview).
- Актуальная главная портала Alfa API перечисляет выписки по счетам юридических лиц и информацию по дебетовым счетам физических лиц в контексте доступа к данным клиентов через интеграцию. Она не подтверждает подключение частным владельцем собственного розничного счёта из standalone iOS приложения. См. [портал Alfa API](https://developers.alfabank.ru/); необходимость/допустимость бизнес-онбординга именно для данного случая всё ещё требует ответа банка.
- В официальной справке Ozon выписку можно запросить через приложение, сайт, отделение или банкомат; каталог документации отделяет Seller API и другие партнёрские API. Публичный API истории личного банковского счёта в этих материалах не обнаружен. Отсутствие в каталоге не доказывает отсутствие закрытого продукта. См. [справку о выписках](https://docs.ozon.ru/common/oplata/bank-statements/) и [каталог документации](https://docs.ozon.kz/main/).
- Решение не меняется: автоматический доступ к личным счетам и прямой iOS OAuth не подтверждены. Не добавлять заглушку подключения, не передавать коды/пароли приложению и не снимать запрет на сервер. До ответа банка остаются локальный CSV-импорт и ручной баланс.
